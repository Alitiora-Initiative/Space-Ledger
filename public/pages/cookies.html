Cookies and browser storage

The current application code does not set or read cookies, local storage, or session storage. It does not load analytics, advertising pixels, or tracking scripts. On that basis, the application does not currently need a cookie-consent banner for its own code. This conclusion must be revisited if the host, a new script, or a future feature adds storage or tracking.

External requests and embeds

The site contains no embedded third-party frames or analytics scripts. Fonts and page code are served locally. When you use a blockchain feature, the server contacts the configured Solana Devnet or EVM RPC provider with the query needed for that feature. A detected wallet is contacted only after you choose a wallet action. Solana Explorer opens only if you follow a receipt link; it is not embedded in this page.

Consent if the site changes

If a future feature stores or reads non-essential information on your device, or adds tracking, the operator must check the rules that apply in each target country. Where prior consent is required, the feature should remain off until you make a clear choice, and refusing should be as easy as accepting. Essential security or delivery storage should still be explained where required. For example, the UK's ICO guidance covers cookies and similar technologies under PECR; it is not a global rulebook.

Changes and contact

This policy should be updated whenever the deployed cookie, storage, analytics, or embed behavior changes. The operator has not yet provided a privacy contact for questions; that contact must be published before the privacy notice is complete.
